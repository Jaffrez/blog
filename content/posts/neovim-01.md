在使用neovim的过程中，我一直习惯于使用hjkl移动光标，
虽然这样完全足够完成日常的编辑，但是当目标位置稍远时，
我就需要反复按键，许多时间并没有花在具体的编辑上，
而是消耗在定位目标的过程中。

在阅读了neovim的用户手册后，我发现之前我忽略了一个问题，
我到底是想要移动光标，还是想要去往某个具体的位置。

## 按单词为单位移动
比如这一行rust代码:  

```rust
let message = "Hello, neovim!";
```

假设我的光标位于行首，而我的目标是message。那么，
按照我过去的习惯，我需要连续按4次l，才能把光标
定位到*m*上。  

在阅读文档后，我发现还可以使用 `w`，直接将光标定位到下一个单词的开头。  

与连续使用四次 `l` 不同，`w` 并不关心光标需要移动多少字符，
而是根据文本内容，直接定位到下一个单词的开头。
这两种操作的区别，并不仅仅在于按键次数。使用 `l` 时，
我需要自行控制光标移动的距离；而使用 `w` 时，我只需要描述想要到达的位置。
也就是说，我开始从「控制光标如何移动」，转向「描述光标应该到达哪里」。

当然，这并不意味着 `w` 一定比 `hjkl` 更好。在需要精确调整光标位置时，
`hjkl` 仍然很方便。

除了 w，还有 b、e 和 ge 等操作，分别用于向前移动到单词开头，
向后移动到单词结尾，以及向前移动到单词结尾。

## 定位到指定字符
那如果我要找的不是一个单词，而是一个具体的字符呢？
```
This is a simple sentence.
```
比如在这句话中，如果我需要定位到'simple'中的'l'
（光标同样位于行首）。
我可以使用`fl`操作，它的含义是：找到下一个'l'字符，
与之前的 `w` 不同，`f` 不再依赖单词边界，
而是根据我指定的字符来确定目标位置。

此外，这些定位操作还可以与编辑命令组合使用。

## 根据文本匹配定位
之前的操作都局限于某一行中，但是，
在整个文件中定位也是常见的场景。
```rust
fn main(){
    hello();
}

fn hello() {
    println!("Hello,world!");
}
```
假如我的光标在第一行，我想要跳转到`hello`函数的定义行，
那我可以使用`/hello`来进行文本搜索，它首先会定位到`main`函数
中的函数调用，接下来，我再使用`n`操作寻找下一个匹配项，
就可以跳转到我想要的函数定义位置。

## 结尾
再次审视这些操作，他们的作用虽然各不相同，但是
都为我提供了一种新的定位方式。  

过去，我需要考虑如何移动光标来到达目标位置，
而现在，我可以直接告诉编辑器我想要去哪里。  

当然，这些操作仍需要大量的练习，才能逐渐替代
我原来的操作习惯。
